# アプリ名（仮）
CampusChef（キャンパスシェフ）

## 概要
ユーザが冷蔵庫にある食材をスマートフォンなどで撮影すると、AIが画像内の食材を自動的に検出し、その食材を使って作れる料理を提案する。

特に、一人暮らしの大学生が「冷蔵庫にある食材で何を作ればよいかわからない」という問題を解決することを目的としている。

画像認識AIと自然言語処理AIを組み合わせることで、食材の検出からレシピの推薦、調理手順の生成までを行うアプリを目指す。

## 想定ユーザ
* 自炊をしたいが、何を作ればよいかわからない大学生

* 冷蔵庫に残っている食材を有効活用したい人

* 食費を節約したい一人暮らしの学生

* 料理のレシピを簡単に検索したい人

* 食材を無駄にせず、食品ロスを減らしたい人

## 主な機能
* 食材画像認識機能
 * ユーザがアップロードした画像からAIが食材を自動的に検出する。
 * YOLOv8やGrounding DINOなどの物体検出モデルを使用する。

* 食材一覧表示機能
 * 検出した食材の名前を一覧で表示する。
 * 検出結果をBounding Box（BBox）で可視化する。

* AIレシピ推薦機能（実装予定）
 * 検出された食材をもとに、作れる料理を推薦する。
 * SBERTなどを利用して食材とレシピの類似度を計算することを検討している。

### AIモデル・API

* YOLOv8（物体検出）
 * 食材を画像から検出するために使用する。
 * 食材データセットを使用してFine-tuningを実施した。
 * 複数のデータセットを用いて学習と評価を行った。
* Grounding DINO（物体検出）
 * テキストで指定した食材を画像から検出できるモデル。
 * YOLOv8との比較実験を実施した。
 * 指定するテキストによって検出結果が変化することを確認した。
 * 今後はBBoxを生成し、YOLOv8の追加学習用データとして利用することを検討している。
* Qwen3.5-4B Vision（実験）
 * 画像から食材を認識する方法として動作確認を行った。
 * 一部の画像では誤認識や不自然な文章生成が発生した。
 * 現在は物体検出モデルを中心に開発を進めている。
* 合成データ生成（Stable Diffusion 3.5 Medium
 * Stable Diffusion 3.5 Mediumを使用して、食材の合成画像を生成することを検討している。
 * 生成した画像にGrounding DINOを適用し、食材のBounding Box（BBox）を自動生成する。
 * BBoxとラベルを確認・修正した後、YOLOv8のFine-tuning用データとして使用する。


## 入力と出力

### 入力

* 食材の画像（JPEG / PNGなど）

### 出力

* AIが検出した食材名

* 食材の位置を示すBounding Box

* 食材検出の信頼度スコア

* おすすめ料理の一覧（実装予定）

* 必要な食材と不足食材（実装予定）

* AIが生成した調理手順（実装予定）



## 工夫したい点

* 食材検出の精度向上
 * YOLOv8とGrounding DINOの検出精度を比較する。
 * 誤認識が発生する原因を調べ、モデルの改善を行う。
* Fine-tuning用データの改善
 * Grounding DINOを使用して食材画像のBBoxを生成する。
 * 生成したBBoxを確認・修正し、YOLOv8の追加学習に利用する。
 * 合成データを利用して学習データを増やすことも検討する。
* 撮影方法の改善
 * 冷蔵庫の中で撮影した場合と、食材を取り出して撮影した場合の違いを調べる。
 * 照明、撮影角度、食材の重なりによる影響を確認する。

## メモ

* 現在の課題
食材の重なりや照明によって検出精度が低下する場合がある。
食材の種類によって誤認識が発生する。
YOLOv8とGrounding DINOでは得意な画像が異なる可能性がある。
Grounding DINOではテキストの指定方法によって結果が変化する。
レシピ推薦機能と調理手順生成機能は今後の開発課題である。
* 今後検討したいこと
Grounding DINOをそのままアプリに採用するか、YOLOv8の学習データ生成に利用するか。
少ない画像データで効率的にFine-tuningする方法。
合成データを使用した場合の精度への影響。
画像認識からレシピ推薦までを一つのアプリとして連携させる方法。
